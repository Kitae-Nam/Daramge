# 공용 보스 기반

체스 보스 1페이즈 전체 사용법, 공부 순서와 연습문제는 [PhaseOneStudy.md](PhaseOneStudy.md)를 참고한다.

체스 보스에 종속되지 않는 체력, 그로기, 패턴 실행 흐름이다. 보스별 AI, 이동, 공격 판정,
페이즈 기준과 소환 규칙은 각 보스에서 구현한다. 기존 씬에는 자동으로 추가하지 않는다.

## 구성과 분리 이유

| 타입 | 책임과 분리 이유 |
| --- | --- |
| `IDamageReceiver` | 공격자가 보스의 구체적인 체력 컴포넌트를 몰라도 피해를 전달한다. |
| `BossHealthModel` | Unity와 무관하게 체력/배율을 계산하고 수치 규칙을 테스트한다. |
| `BossHealth` | Inspector의 최대 체력과 모델을 연결한다. 체력바/페이즈는 이벤트를 구독한다. |
| `BossGroggyController` | 그로기 시간과 취약 배율만 관리한다. 이동/애니메이션은 이벤트로 연결한다. |
| `BossPattern` | 경고/실행/정리 계약이다. 보스별 공격은 상속으로 추가한다. |
| `BossPatternRunner` | 한 번에 하나의 패턴을 실행하고 경고, 후딜, 패턴 간 휴식을 보장한다. |

단일 거대 Boss 클래스를 상속시키는 대신 컴포넌트를 조합한다(SRP).
새 패턴은 `BossPattern`을 확장하므로 실행기를 변경하지 않는다(OCP).
AI는 패턴 계약과 `TryRun`에, 공격자는 `IDamageReceiver`에 의존한다(DIP).

## Unity 연결

1. 보스 루트에 `BossPatternRunner`를 추가한다. 필요한 체력/그로기 컴포넌트도 자동 추가된다.
2. `BossHealth`에서 최대 체력, `BossGroggyController`에서 그로기 시간/배율을 설정한다.
   기본 그로기는 3초, 받는 피해는 1.5배다. 시간은 `Time.deltaTime` 기준으로 일시정지를 따른다.
3. 패턴마다 `BossPattern`을 상속한 컴포넌트를 만들고 `Execute()`에서 공격 코루틴을 구현한다.
   `CanExecute()`에서는 사거리/소환 여부를 검사한다. 준비 중 조건이 바뀌면 공격을 취소한다.
   경고 시작 시 공격 위치를 저장하고 경고 표시와 실제 공격에 같은 위치를 사용해야 한다.
4. 패턴의 Warning Started/Ended 이벤트에 경고 오브젝트 표시/숨김 함수를 연결한다.
   실행기는 경고 시간을 보장하지만 실제 경고 그래픽은 각 패턴에서 연결해야 한다.
5. 보스 AI에서 `runner.TryRun(pattern)`을 호출한다. 반환값이 false면 현재 실행 중이거나
   그로기/사망/쿨타임/패턴 조건으로 시작할 수 없는 상태다. 자동 패턴 선택은 포함하지 않는다.
6. `Cleanup()`에서 히트박스, 이동, 경고 외 임시 이펙트를 해제한다. 정상 완료, 사망, 그로기,
   실행기 비활성화와 명시적 취소 모두에서 호출되므로 여러 번 호출해도 안전하게 작성한다.
   공격 도중 독립적인 `StartCoroutine`을 시작하지 말고 중첩 `IEnumerator`를 yield한다.
   `Execute()`는 비어 있어도 `yield break`를 사용해 유효한 iterator를 반환해야 한다.
7. `StateChanged`, `Entered`, `Exited`, `HealthChanged`, `Died`를 구독해 애니메이션과 UI를 연결한다.
   구독한 컴포넌트는 비활성화 시 구독을 해제한다. 사망 상태는 다시 공격을 시작할 수 없다.

패턴 쿨타임은 시작이 수락될 때부터 계산한다. 공통 휴식은 후딜이 끝나거나 중단된 시점부터
추가로 적용된다. 기본 설정은 경고 1초 → 공격 → 후딜 1초 → 공통 휴식 1초다.
그로기는 남은 시간을 더 짧게 만들지 않는 방식으로 갱신하며 배율을 중복 적용하지 않는다.
체력과 쿨타임은 컴포넌트 비활성화로 초기화되지 않는다. 재사용/부활은 별도 정책이 필요하다.

## 피해 배율 계약

`health.SetDamageMultiplier(source, multiplier)`로 효과 소유자별 배율을 등록하고,
효과가 끝나면 `health.RemoveDamageMultiplier(source)`로 본인 배율만 해제한다.
같은 소유자를 다시 등록하면 기존 배율을 교체한다. 0배는 무적이며 음수/NaN/무한대는 거절한다.

모든 배율은 곱셈이다. 소환 보호 0.5배와 그로기 1.5배가 공존하면 최종 피해는 0.75배다.
그로기 중 소환 보호를 없앨지는 체스 보스의 규칙으로 처리한다.
`ReceiveDamage()`는 남은 체력을 초과하지 않는 실제 감소량을 반환하며 사망 이벤트는 한 번 발생한다.
최대 체력 설정은 최초 초기화 시 적용되므로 플레이 중 Inspector 수정으로 재설정되지 않는다.

## 검증

Unity의 Test Runner → PlayMode → `Daramge.Bosses.Tests`를 실행한다.
배율 중첩/독립 해제, 잘못된 수치, 사망 이벤트, 경고 순서, 휴식 시간,
그로기/사망/비활성화 시 취소와 iterator 정리를 확인한다.

Unity 6000.6.3f1의 별도 검증 프로젝트에서 실제 PlayMode 테스트를 실행한다.
공용 체력/러너 검사에 더해 대쉬, 1페이즈 프리팹 상호작용, 저장된 테스트 씬의 자동 전투를 검사한다.
