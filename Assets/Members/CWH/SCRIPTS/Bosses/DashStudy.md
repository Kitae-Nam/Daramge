# 1페이즈 대쉬 사용법과 학습 순서

## 실행

`DEV_SCENE`의 `The_King(Boss)`에 대쉬를 연결했다.
작업 중 Unity에서 씬을 열어 두었다면, 편집 모드에서 **CWH > Boss > 대쉬 연결 및 저장**을
한 번 실행한다. 현재 에디터에 열려 있는 씬에도 컴포넌트를 연결하고 저장하는 메뉴다.
이미 연결된 컴포넌트는 다시 만들지 않는다.
플레이 모드에서 `Dash Pattern` 컴포넌트 제목을 우클릭하고 **테스트/대쉬 패턴 요청**을 선택한다.
체력 0, 그로기, 다른 패턴 실행 중, 쿨타임 중에는 요청이 거절된다.
경고가 끝난 뒤 이동하므로 테스트 대상은 파란 Gizmo 경로에 놓고 확인한다.

기본 설정은 경고 1.2초, 거리 18, 초당 이동 거리 30, 폭 4, 피해 25, 후딜 0.8초다.
공통 휴식과 개별 쿨타임은 기존 러너의 규칙을 사용한다.
거리/속도/폭/피해는 `DashPattern`, 물리 장애물 레이어는 `BossDashMotor`에서 조절한다.
피해 대상 레이어는 `DashHitbox`에서 조절한다. 이 값들은 보스 부모의 스케일과 별개인 월드 단위다.

테스트 블록에는 `TestDamageReceiver`를 추가했다. 실제 피해가 들어오면 Console에 감소량과 남은
체력을 출력하며 Inspector의 Current Health에도 반영한다. 실제 플레이어 체력이 완성되면
테스트 컴포넌트 대신 `IDamageReceiver`를 구현한 플레이어 체력을 연결하면 된다.

## 부품별 역할

| 파일 | 하는 일 | 따로 둔 이유 |
| --- | --- | --- |
| `Patterns/DashPattern.cs` | 경고 → 돌진 → 정리 순서 | 보스 패턴의 순서를 다른 기술에서 분리한다. |
| `BossDashMotor.cs` | 경로 계산, 직선 이동, 장애물 앞 정지, Agent 설정 복구 | 이동 코드에 셰이더와 체력 계산을 넣지 않는다. |
| `DashHitbox.cs` | 이동 구간의 명중 확인, 한 번만 피해/밀치기 요청 | 공격 판정은 이동/표시와 독립적으로 검사할 수 있다. |
| `DashTelegraphPresenter.cs` | 경고 평면의 위치·방향·크기 배치 | 셰이더 값 변경은 기존 `BossTelegraphPresenter`를 재사용한다. |
| `TEST/TestDamageReceiver.cs` | 테스트용 체력과 피해 로그 | 미완성 플레이어 체력에 대쉬를 종속시키지 않는다. |

## 코드를 읽는 순서

1. `DashPattern.BeginWarning()`부터 본다. 플레이어를 향한 방향을 한 번 저장하고 경고를 만든다.
2. `UpdateWarningProgress()`는 러너가 준 0~1 값을 기존 셰이더에 전달할 뿐, 별도 타이머를 만들지 않는다.
3. `Execute()`는 저장된 방향으로 이동한다. `speed * Time.deltaTime`은 이번 프레임의 이동 거리다.
4. 각 이동 전후 위치를 `DashHitbox.Sweep()`에 전달한다. 한 프레임에 대상 너머로 이동해도 그 사이를 검사한다.
5. `DashHitbox`의 `HashSet`은 이미 맞은 대상을 기억한다. 같은 대상의 Collider가 여러 개여도 반복 피해를 주지 않는다.
6. 정상 완료 전에 `finally`에서 판정을 끈다. 따라서 후딜 동안 몸에 닿았다고 새 피해를 주지 않는다.
7. 그로기/사망은 러너가 코루틴을 중단하고 `Cleanup()`을 호출한다. 경고, 판정, Agent 설정이 함께 정리된다.
8. 마지막으로 경고 배치 수학을 본다. Mesh의 UV 방향을 실제로 읽어 Plane과 Quad 모두에서 채움 방향을 맞춘다.

## 경고와 경로를 맞추는 방법

`DashPath`에는 시작점, 고정 방향, 실제 이동 가능 거리가 들어 있다. 경고와 이동은 같은 값을 사용한다.
일반 추적과 달리 경고 후 플레이어를 따라 방향을 다시 계산하지 않는다.
처음부터 벽이 있으면 예고 거리도 줄인다. 경고 후 장애물이 새로 생기면 돌진을 일찍 멈춘다.
장애물이나 NavMesh 경계에 막혔다고 우회하거나 순간이동하지 않는다.

셰이더의 `_OutRectangleW`, `_OutRectangleH`는 평면 전체 중 경고가 차지하는 UV 비율이다.
예를 들어 폭 4를 경고로 보여 주고 UV의 0.8만 사용한다면 메시 전체 폭은 `4 / 0.8 = 5`가 필요하다.
경고 배치 코드는 이 비율과 Mesh의 실제 크기를 반영한다. 기본 Plane/Quad와 해당 프로퍼티를 가진
현재 경고 셰이더를 사용한다. 임의의 굽은 메시나 다른 방식의 UV를 사용하는 셰이더는 대상이 아니다.

평면은 경고 중에만 보스 부모에서 분리되어 월드에 고정되고, 숨길 때 원래 부모와 로컬 배치로 돌아간다.
공유 머티리얼의 값을 바꾸지 않고 기존 MaterialPropertyBlock 방식으로 진행도/투명도를 변경한다.

## 확인할 상황

- 경고 중 플레이어가 옆으로 피하면 돌진이 쫓아오지 않는다.
- 경로 위에 남으면 피해와 밀치기를 한 번 받는다. 범위 밖에는 적용되지 않는다.
- 벽 앞에서는 경고 경로가 줄거나, 새 장애물이 생긴 경우 실제 이동이 조기에 끝난다.
- 경고/돌진 도중 그로기 또는 사망을 발생시키면 경고와 명중 판정이 남지 않는다.
- 후딜에는 공격 판정이 없고, Idle로 돌아오면 기존 추적과 회전이 재개된다.

1페이즈 직선 돌진을 구현한 상태이며 2페이즈 장판, 자동 패턴 선택, 검 자세/돌진 애니메이션과
소리/카메라 연출은 포함하지 않는다. NavMesh와 물리 충돌이 일치하도록 벽 Collider와 Bake도 유지해야 한다.

## 직접 풀어 볼 문제

1. `BeginWarning()`에서 방향을 저장하지 않고 `Execute()` 매 프레임 대상 위치로 방향을 계산하면 무엇이 달라질까?
2. 초당 속도가 30이고 한 프레임이 0.02초라면, 그 프레임의 요청 이동 거리는 얼마일까?
3. `DashHitbox`에서 `HashSet`을 제거하면 어떤 상황에서 피해가 여러 번 들어갈까?
4. 코루틴을 멈추기만 하고 `BossDashMotor.Stop()`을 호출하지 않으면 어떤 Agent 설정이 남을까?
5. Plane 전체 폭이 10이고 셰이더가 UV 폭 0.8을 사용한다면, 경고 폭을 4로 만들 스케일은 얼마일까? 부모 스케일은 1로 가정한다.
6. 러너의 Recovery가 끝날 때까지 공격 판정을 켜 두면 어떤 문제가 생길까?

답은 먼저 직접 설명해 보고 확인한다. 암기보다 각 함수가 왜 필요한지 말할 수 있는 것이 목표다.
